# 多节点

本专题展开"单机是分布式的退化形式"。Space 是主人全部节点的集合：在手机上说话、由 VPS 思考、用桌面的 IDE、再拍一张手机照片，是一个 Session 的正常状态。这里的判断也决定了单机时的数据形态。

### 单机阶段就固定事后补不上的数据形态

Event、Round、调用与插件使用全局唯一 ID，接收方去重；Log 键为 `(epoch, seq)`，单机时 epoch 恒为 1；Session 带 Binding；能力 ID 带节点；blob 与制品内容寻址；composer 是确定性的纯函数。这些事后补上代价很高，所以现在就遵守。机制在真正需要时再引入：Space 级的可变记录单机时由本地 SQLite 带前置条件写入，共识与随之而来的 trait 在第二个实现出现时才加。

### 顺序来自结构，不来自时钟

Log 的顺序由归属者分配的序号决定，Space 级记录的顺序由控制平面的日志位置决定。墙钟时间只用于展示，以及带有人类时间语义的事情，例如"明天九点提醒我"。唯一依赖时钟的正确性规则是租约到期，它只在本机测量，不跨节点比较时钟。所以节点之间的时钟偏差影响不了任何事实的先后。

### 三种位置相互独立

在哪里看、在哪里说，是界面位置，任意节点都可以订阅与投递；下一个 Round 在哪执行，是执行位置，由 Binding 决定；工具在哪里运行，是能力位置，由能力 ID 上的节点决定。三者独立，所以一个 Session 用到多台设备时不需要迁移。

### 跨节点只有两个原语

`invoke` 把一次调用送到别的节点（Erlang 的 `rpc:call`、Plan 9 的 `import`），`roam` 让 Session 到别的节点继续执行（Plan 9 的 `cpu`）；委派是创建子 Session 再把它的 Binding 指向目标节点。远程调用的请求发出后连接断开，一律返回 `unknown`，位置透明不掩盖部分失败。跨节点时不钉住代际，而是携带 schema 哈希，不一致就明确返回未执行。模型可见的工具名不含节点，否则工具列表随节点数成倍增长。

### 漫游的是 Session，只在 Round 边界提交

持有者先停止执行，再在控制平面上以 CAS 把 Binding 推进到新的 epoch，然后通知目标节点；目标节点等副本追上要求的位置，再开始下一个 Round，并重新计算能力快照。身份、Log 与工作区随 Session 一起走，运行时实例不迁移。漫游的发起者可以是 Agent、策略或主人，三者走同一个内核命令。

### 可变的东西小，交给共识；大的不可变或只有单一写者

成员、Binding 与租约、期望状态、git 引用小而低频，放在控制平面，由 Raft 维护线性一致。Session Log 与插件状态只有一个写者，按 epoch 栅栏异步复制，副本只会落后，不会分叉；blob、制品与 git 对象内容寻址，按哈希拉取。数据平面因此没有需要合并的冲突。这是 git、Nix、Datomic 共有的结构。共识属于正确性极难的地基，使用 openraft。

### 宁可暂时不可用，也不出现两个执行者

Session 是粘滞所有权：持有者不需要续约，与控制平面失联也能继续执行自己持有的 Session；所有权只能由持有者让 Session 漫游出去，或者由主人确认强制接管。渠道连接与定时是租约：续约失败超过安全余量时持有者自行停止，控制平面只在旧租约过期后授予新租约，所以渠道可以自动接管，同时任何时刻只有一个节点在轮询。租约计时用计入休眠的单调时钟，笔记本合盖唤醒后才不会误以为租约仍然有效；每次对外发送之前都检查租约。外部服务看不到 epoch，所以服务支持幂等键时，用 `(session, epoch, round, call-id)` 作键，`unknown` 的含义不变。

### 少数派一侧只继续自己持有的东西

分区时，少数派一侧可以继续执行自己持有的 Session，也可以新建 Session，全新的 key 不会冲突；不能漫游出去，也不能接管别处的 Session，发往别处的消息进入 outbox，重连后以事件 ID 去重投递；它无法续约，会在 TTL 内释放渠道租约，让多数派一侧接管。这是 CP 的代价，界面上要说清楚。

### 强制接管须主人确认，是唯一可能分叉的路径

确认界面显示已复制到的最后位置，主人知道可能丢失哪段尾部。旧持有者如果其实还活着，重连后看到更高的 epoch 会立即停止，它尚未复制的尾部作为分叉保留，并在主线的下一个 Round 对模型可见。

### 复制与上下文是两个轴

复制决定节点存了什么（全量日志或仅本地，blob 与制品按需拉取），Brief 决定模型看到什么（完整历史或摘要加可展开的引用）。四种组合都有用途：换设备继续对话、派出一个干净的子任务、委派给不做复制的节点、隐私会话。Brief 由模型按 schema 生成，两端都写入 Log，目标节点可以经 `invoke` 回到源头按需展开。

### 实时路径不承载持久路径之外的事实

每对节点之间一条认证的连接，承载调用、结果、流、同步、漫游与共识的帧。实时路径只是更快地传递已经持久化或将被持久化的东西，不独有任何事实；可达性交给 Tailscale、WireGuard 这类载体。

### 修复一次，处处生效

期望状态（已登记的意图、已批准的集合、skills 的提交）在控制平面，在任何节点上修好一个插件，其他节点都会收到；实际状态与健康按节点记录，制品按哈希向同伴拉取。系统代际是宿主版本、活跃插件代际、活跃配置代际与 skills 提交的组合，可以命名、比较与整体回滚；新设备加入时采用期望状态，就得到同一套能力。同伴节点互为 supervisor，可以经 `invoke` 诊断彼此。单节点时，期望状态就是本机已登记的意图，实际状态就是运行中的代际。

### Space 只属于主人

信任模型是单一所有者：完整节点默认把全部能力导出给 Space；节点身份是配对时交换的 ed25519 密钥；密钥按接收节点的公钥加密后在 Space 内复制，这是渠道故障转移的前提，单个密钥可以设为仅本地。远程 `invoke` 在被调方留下审计记录。

### 手机在进入后台前漫游回常驻节点

手机在前台时是完整节点与控制平面的 learner，可以持有 Session、使用本地工具；进入后台前，策略让它持有的 Session 漫游回常驻节点，绕开移动系统的后台限制。设备能力（通知、定位、相机）以远程能力导出，需要前台而条件不满足时返回明确的错误。重计算不放在 iOS 本地，经 `invoke` 交给 VPS 或桌面。离线时遵循少数派的规则。
