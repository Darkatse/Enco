# 工程

本专题展开"在源头声明，不在下游防御"与"概念少而一致"在代码组织上的含义。维护者包括人与 Agent，代码的结构本身就是给他们的说明：一件事情在哪里、由谁负责，应当从结构上看得出来。

## 结构

### crate 按概念划分，按触发条件拆分

依赖方向是 `enco-core` ← `enco-kernel` ← `enco-host` / `enco-wasm` ← `apps/enco`，已经满足 Clean Architecture 的依赖规则：core 是实体，内核端口与 WIT 是端口，内核是用例，宿主、Wasm 运行时与插件是适配器，`apps/enco` 是组合根。所以 crate 的名字就是设计中的概念，命名沿用设计的词汇。只有出现明确的边界、独立的依赖成本或稳定的变化原因时才拆分。已知的第一个拆分点是 `enco-host`，它同时承载 Host 机制与原生能力；插件第一次需要 Host 机制提供的宿主导入时拆开，在那之前保持模块级的分隔。

落点：`cargo xtask boundaries` 检查依赖方向；每个插件、SDK 与评测运行器各是独立的工作区，引用不了宿主的 crate。

### 调用关系全部写在组合根与端口上

依赖在组合根一次构造成具体的结构体，组件之间只经端口交互，读代码就能看到谁调用谁。trait 只放在真实的边界上（内核端口、宿主与插件、渠道协议适配器），或者在第二个实现出现时再引入。共同的代码提取为普通函数。文件按它回答的问题命名，例如 `recovery.rs`、`transcript.rs`、`plan.rs`，模块按职责拆分；crate 之间只暴露必要的类型与函数。

### 文件与函数都要能一次读完

维护者（人或 Agent）通常整份读一个文件、整段读一个函数，过长的文件或函数往往同时回答了两个问题。超出上限时按职责拆分，拆出的部分自己回答一个问题；只有平铺的分派（例如协议命令到归属者方法的对照）用带理由的 `expect` 放行。上限只用来报出问题，拆分的依据始终是职责。

落点：`cargo xtask check` 检查源文件与测试文件的行数，clippy 的 `too_many_lines` 检查函数的行数。

## 约束的位置

### 可调的只有配置表，其余是常量

每个可调项都是一条要维护的分支，也是 Agent 需要知道的一个事实。所以可调的只有各归属者的配置表与少数几个环境变量，本仓库的 crate 不定义 Cargo feature；其余一律是常量，集中在各 crate 的 `limits.rs` 中。面向模型的文本中出现的上限由这些常量生成。

### 归一化与校验只在拥有事实的地方做一次

工具参数的归一化与参数名检查只在内核的分派中，工具只校验自己读取的值；配置只由表的归属者校验，插件配置只由 `describe` 校验。持久化的前置条件由 Store 在事务里检查，失败就让归属者停止并报告原因。其余各层信任这些边界。

### 错误按含义建模

库 crate 用 `thiserror` 定义错误，放在产生它的模块中，一个变体只表达一种含义；`anyhow` 只在应用边界。错误消息带上定位信息，例如 Session、Log 位置或路径。只有已知的、语义明确的情况才有恢复路径，并且对调用方可见；未知的状态直接报错。

### 后台任务只属于归属者

每个后台任务都是一个归属者，或者归属者为了等待外部而派出的助手。派生状态在使用前与权威对账，不靠后台任务维持。新增长期运行的任务需要先与主人对齐。

## 持久格式

### 持久格式只支持当前版本

库的版本不等于当前版本时拒绝启动，不改动库。承诺跨版本升级之前，没有使用者的兼容代码只是负担，所以只读写当前格式；承诺升级不丢记录时，再设计迁移。配置与协议的输入拒绝未知字段，Log 条目接受，新增的可选字段对旧的读取者无害。

## 安全与构建

### 宿主不写 unsafe

宿主进程的内存安全是插件边界成立的前提，所以宿主代码禁止 unsafe，经过审计的依赖（wasmtime、TriviumDB）内部的不在此列。插件运行在沙箱里，其中的 unsafe 最多让插件自己 trap，由健康门控回退，所以插件侧只约束写法：源码不手写 unsafe，生成的导出胶水以带理由的 `expect` 接受。

### 出厂插件保持干净构建

出厂制品按内容寻址，字节一变就是一个新的出厂代际，每次宿主升级都会触发跟随。宿主自己的 crate 以 IO 调度为主，release 构建开启增量编译，换取改动后的重建速度；插件工作区不跟：不开增量，同一工具链下的相同源码才得到相同的字节。

### 性能从减少搬运开始

Wasm 的开销相对模型延迟可以忽略，优化的重点在数据搬运：传引用，按范围读，大对象用流。实时路径使用有界队列，慢订阅者被断开，数据源不被拖慢。需要持续测量的是端到端的指标：改动到可用的时间、漫游延迟、渠道故障转移时间、冷启动、内存，以及反复登记后的资源残留。复杂度要有测量结果支撑。
