# 记忆

本专题展开"归属与转移"中派生状态的规则。个人化的长期记忆是私人助理的核心能力；这里的判断让记忆的更正与遗忘总是生效，让索引的任何问题只影响召回质量，不影响正确性。

### 内核不知道记忆

记忆是宿主的能力，经内核已有的两个端口接入：写入与搜索是工具，召回是上下文来源。内核不为它增加任何概念。记忆的记录与索引是宿主的机制，TriviumDB 依赖 mmap 与线程，进不了 Wasm；召回与写入的策略可以改为插件，经宿主导入使用索引。

### 权威是记录，索引是权威的函数

权威是宿主 SQLite 中的记忆记录，由唯一的归属者写入，一个归属者一个文件。检索索引是权威与 embedding 身份的函数：写入只改权威，不触碰索引，也不留下任何标记；每次召回前，同一个对账函数比较两者并补齐差异。所以不需要记住"哪些还没进索引"，对账被取消、失败或与写入并发，都没有需要恢复的东西。对索引有任何疑问，就删掉重建。数据形态（全局唯一 ID、修订号、权威与派生分开）也满足多节点复制的要求。

代价：每次召回读一遍全部记忆的 `(id, rev)`，个人规模下是毫秒级。

### 索引提名，权威裁决

检索命中的每一条，都回到权威读取当前内容后才能进入上下文，权威中已经不存在的直接丢弃。过期的索引因此只影响召回的质量，永远不会让已更正或已遗忘的内容重新出现。尚未进入索引的记忆按更新时间直接出现在召回结果中。

### 遗忘就是删除

遗忘删除权威中的记录，权威不保留被遗忘的内容；更正替换记录。被遗忘的内容仍留在当时那个 Session 的 Log 中，这是 Log 的性质，不是记忆的。

### 索引的身份是向量空间的全部定义

索引的身份由 embedding 的 `base_url`、`model`、`options` 与维度组成；`options` 整体纳入，因为宿主不解读它，无法知道哪一项影响向量空间。身份变了就删掉重建：多重建一次是安全的，混用两种向量空间不是。endpoint 的名字、密钥变量与插件不在身份中，它们不改变向量。换 embedding 模型就是换向量空间，所以 embedding 只有一个 endpoint。

### 置顶记忆排在最前，仍受预算约束

置顶记忆每个 Round 从权威读取，不依赖检索，也不依赖某次摘要恰好提到它们；其余记忆按最新的输入召回。候选的顺序就是优先级：置顶的在前，召回的在后，composer 按顺序纳入直到预算用完，超出的照实记为省略，Round 不因此失败。

### 权威读不出来时这一轮失败

embedding 不可用时召回只按关键词进行，相关性判断失败时不过滤，它们都只让召回变宽，对话照常进行。权威本身读不出来时，这一轮明确失败：缺了权威，就无法保证召回的内容是当前的。

### 相关性过滤只问记忆与输入是否有关

检索固定取前若干条，因为相似度的尺度依赖具体的 embedding 模型；是否相关交给可选的决策接口判断，它返回概率，阈值由宿主决定。问题问的是记忆与输入是否有关：误删一条需要的记忆，代价比多带一条边缘记忆大，所以只有讲无关之事的记忆才应被滤掉。过滤只作用于自动召回，`memory_search` 的结果由 Agent 自己判断，置顶记忆总是提供。
