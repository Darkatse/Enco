# 渠道

本专题展开"归属与转移"在渠道上的应用。渠道是 Enco 与外界之间最容易出错的地方：连接会断，消息会重复，发出去的请求可能没有回音。这里的判断让每一条入站消息恰好被接纳一次，让每一次出站投递都有一个如实的结局。

### 聊天是壳，Session 属于 Enco

渠道中的聊天只是界面位置，Session 的历史与策略由 Enco 持有。私聊默认挂到 `main`，主人可以切换或新建；群各自新建 Session，边界的理由见 Session 专题「公开聊天与私人助理分属不同的 Session」。名字相同不足以认领一份历史，因此群只认自己创建并记下的 Session 身份。

群里的话多数说给其他人听，只有发给 bot 的消息才驱动 Session，默认只认主人；主人可以对一个群开放成员提问。是不是发给 bot 由映射器解释，是不是主人由宿主在接纳时核对并记下，后来的配置变化不重写过去的身份。命令不经过模型，写法由映射器识别，含义与授权由宿主掌握。此前的消息可以按主人设置的范围随提问交出，作为带发送者的引用；它们不单独驱动 Session，附件也只说明是什么。

### 连接的归属者持有路由，映射器只解释协议

每个账号只有一个连接归属者，它持有协议状态、聊天与 Session 的关系、前文与出站进度。配置名只是入口，协议与账号才标识这些事实：换密钥或改名不应失去历史，换账号也不应继承旧账号的路由。账号身份由映射器解释，宿主不从凭证格式推导身份。

映射器从响应返回带协议键的更新与下一份状态，传输与提交都归宿主。消息、命令与引用前文都可能被重发，所以接纳的单位是整条更新；新接纳的键、状态与输入一次提交，效果只跟随新接纳的事实。重发只推进协议进度，既不重做命令，也不重复积累前文。协议键按协议的承诺使用：Telegram 在一周没有更新之后随机选取下一个 `update_id`，它与已接纳的键相同的概率可以忽略，相同时那条更新被当作重发。响应进入映射器前记录完整调用，失败与规范值都能回到同一份原文；记录的边界见插件专题。

附件下载是读取工作，不占用连接的归属者，因此慢下载不阻塞已有回复的投递。内容先存入 Enco 的库，再随 Event 提交引用；没有提交的内容至多成为无人引用的 blob。无法查看的附件也是输入的事实，随消息记录原因，由 composer 告知模型。

落点：`ChannelAdapter` 返回规范值；连接归属者经 `Kernel::accept` 提交更新与输入。

### 投递是壳在渲染 Log

归属者以出站游标跟随它送过 Event 的每个 Session，与入站游标对称；订阅只用来唤醒，内容一律从 Log 读取，订阅积压丢了消息也从游标重新读。Agent 交给主人的内容有两个生产者：Round 的回复与 `message_send` 记下的消息，共用路由与投递结算；消息一经结算就投递，回复等 Round 以回复结束才投递。它们发往该 Session 最近一条交互式输入的来源，提醒触发的 Run 因此发往主人最近说话的地方。每个壳读同一份 Log 得出同一个结论，彼此不需要协调；CLI 显示 Run 结局的方式与渠道相同。

出站内容是 Markdown 文字加可选的文件，由各生成方按 Markdown 书写，映射到渠道协议是映射器的事。协议能原生显示、并满足其成文限制的就原生显示，其余按原样文件发送。

### 每次逻辑投递恰好一条如实的结算

投递之前先记下"正在投递"，结局（`ok`、`failed` 或 `unknown`）与游标的推进在同一次提交中写入。请求确定没有到达的才重试；已经发出、结果无法确认的记为 `unknown`，不自动重发，5xx 也算在内，因为网关可能在转发之后才出错。启动时发现上次留下的"正在投递"，说明进程在发送途中停止，同样记为 `unknown`。结算只引用 Session 与 Log 位置，不复制正文；一次失败结算之后继续处理后面的消息，不会卡住连接。

### 停止是取消轮询，再等在途的投递结算

停止渠道时，先取消轮询与订阅，丢弃长轮询的请求是安全的，它没有外部效果；然后不再开始新的投递，等正在发送的那一次完成并结算，已经发出的请求不能丢弃。停止期间产生的回复，下次启动时从 Log 补发。

### 渠道换代承诺的是可恢复

替换渠道代码时默认在事件边界切换回调；新代码接续不了当前的协议状态，就按协议重连并补收，例如 Telegram 用 offset，Discord 用 RESUME。一次替换可能短暂断线，其间的消息由补收取回。渠道是视图的函数：配置或所用映射器的代际变了，旧连接一退出就按最新的视图启动，即使旧连接的结算失败了，因为它已经静止；只有归属任务没有正常退出、无法证明静止时才停下并报错。

### 渠道的故障只停下渠道

token 无效、连接状态损坏或配置解析不了时，渠道停止，原因写进 `enco status`，CLI 与其他 Session 照常工作。网络错误按退避重试，守护进程照常运行。
