# M22 出了问题仍能思考

> 路线图 P2 的第 4 个里程碑。计划的生命周期见 spec 09 §5。

## 目标

代码或服务出了问题时，Agent 仍能思考，并能经正式路径修复（§1.2、§4.6）：正常路径的 Round 失败后进入安全模式，主 endpoint 不可用时由备用 endpoint 接替。两者正交，分别落在 Round 层与 Attempt 层。

## 范围

- **安全模式的进入**：正常路径的 Round 失败后，本 Run 之后的 Round 进入安全模式，直到快照改变；新的 Run 从正常路径开始。失败记下失败那一刻的快照标识，Round 内的自动回退算在失败之前。它现在就需要：P1 起就能部署非出厂的 Provider 代码，一个每次都返回普通失败的坏代际会一直停在试用中，Agent 无法思考。
- **备用 endpoint**：profile 的回复与压缩各是一个有序的 endpoint 列表。一个 endpoint 的重试用尽后，为下一个重新组装，开始新的 Attempt；本 Run 中用尽过的 endpoint 在快照改变之前跳过。安全模式的 Round 里同样从列表第一个开始。
- **对模型可见**：出厂 composer 写明进入安全模式的原因与回到正常路径的条件，以及换用 endpoint 的原因。

## 规格

- 03：Round 失败时记下的快照标识。
- 04 §6.1、§6.3、§6.4、§7：Round 失败后进入安全模式，删去"等出现非出厂策略"；endpoint 列表与换用时的重新组装。
- 05 §4：出厂 composer 的说明。
- 12：每个用途是有序的 endpoint 列表。

## 验收

- 部署一个每次都返回普通失败的 Provider 代际：同一 Run 的下一个 Round 进入安全模式，计划中写明原因；Agent 用 `plugin_rollback` 回退它，再下一个 Round 回到正常路径。没有任何改动时，本 Run 余下的 Round 都在安全模式，下一个 Run 从正常路径开始。
- 试用代际 trap，自动回退之后的重试仍然失败：下一个 Round 直接进入安全模式，不在回退后的快照上再试正常路径。
- 上下文来源失败：不请求备用 endpoint，下一个 Round 直接进入安全模式。
- 主 endpoint 返回 402：同一个 Round 内为备用 endpoint 重新组装并成功，计划中写明换用的原因；本 Run 之后的 Round 不再请求主 endpoint，下一个 Run 先请求主 endpoint。
- 主人打开了安全模式开关时，Round 失败就结束 Run。
