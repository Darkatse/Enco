# M22 出了问题仍能思考

> 路线图 P2 的第 4 个里程碑。计划的生命周期见[路线图](../Roadmap.md)。

## 目标

代码或服务出了问题时，Agent 仍能思考，并能经正式路径修复（代际专题）：正常路径的 Round 失败后进入安全模式，主 endpoint 不可用时由备用 endpoint 接替。

## 对齐的判断

- **代码与服务是两条正交的路线**（代际专题）：回退与安全模式处理代码，备用 endpoint 处理服务。每个机制落在它所改变之物被固定的那一层，也只记住这一层固定的东西：安全模式在 Round 层，记住失败时的快照；换 endpoint 在 Attempt 层，记住用尽过的（endpoint 的参数, Provider 代际）组合。
- **不给失败分类**：每个失败一次只落在一条路线上，trap 与契约违规走回退，其余失败在重试用尽后换 endpoint，全部用尽才进入安全模式；安全模式救不了的失败，再失败一次几乎没有代价。
- **没有需要退出的状态**：是否处于安全模式、跳过哪些 endpoint，都只取决于主人的开关与本 Run 的 Log；原因消失后自然恢复，新的 Run 从头开始。
- **备用 endpoint 不是回退**：它是已登记的配置中的另一项，运行中的行为仍然只来自已登记的代际。

## 范围

- **安全模式的进入**：正常路径的 Round 失败后，本 Run 之后的 Round 进入安全模式，直到快照改变；新的 Run 从正常路径开始。失败记下失败那一刻的快照标识，Round 内的自动回退算在失败之前。它现在就需要：P1 起就能部署非出厂的 Provider 代码，一个每次都返回普通失败的坏代际会一直停在试用中，Agent 无法思考。
- **备用 endpoint**：profile 的回复与压缩各是一个有序的 endpoint 列表。一个 endpoint 的重试用尽后，为下一个重新组装，开始新的 Attempt。本 Run 中用尽过的（endpoint 的参数, Provider 代际）组合不再尝试，两者都已记在 `AttemptStarted` 中，不需要新的记录；安全模式用出厂代际，组合不同，列表自然从头尝试。
- **对模型可见**：出厂 composer 写明进入安全模式的原因与回到正常路径的条件，以及换用 endpoint 的原因。

## 设计

- 代际专题的「每个恢复机制落在它所改变之物被固定的那一层」与「安全模式是开关与本 Run 的 Log 的函数」已按本计划写入，验收时按实现核对。
- 先定下的格式：Round 失败时 Log 记下的快照标识；profile 中每个用途的有序 endpoint 列表（`config.toml`）。

## 验收

- 部署一个每次都返回普通失败的 Provider 代际：同一 Run 的下一个 Round 进入安全模式，计划中写明原因；Agent 重新部署上一个代际的制品（M21），再下一个 Round 回到正常路径。没有任何改动时，本 Run 余下的 Round 都在安全模式，下一个 Run 从正常路径开始。
- 试用代际 trap，自动回退之后的重试仍然失败：下一个 Round 直接进入安全模式，不在回退后的快照上再试正常路径。
- 上下文来源失败：不请求备用 endpoint，下一个 Round 直接进入安全模式。
- 主 endpoint 返回 402：同一个 Round 内为备用 endpoint 重新组装并成功，计划中写明换用的原因；本 Run 之后的 Round 不再请求主 endpoint，下一个 Run 先请求主 endpoint。
- 主 endpoint 用尽之后，部署一个无关插件的新代际：本 Run 之后的 Round 仍不请求主 endpoint。
- 主 endpoint 已用尽，Provider 的活跃代际就是出厂代际：之后因为别的原因（例如上下文来源失败）进入安全模式时，安全模式的 Round 不再请求主 endpoint，直接用备用的。
- 主人打开了安全模式开关时，Round 失败就结束 Run。
