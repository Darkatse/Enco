# M29 composer 插件

> 路线图 P2 的第 11 个里程碑。计划的生命周期见[路线图](../Roadmap.md)。

## 目标

默认 composer 改为 Wasm 插件，Agent 以评测成功率为目标、以 Attempt 记录的用量（含缓存命中）为成本约束迭代它（上下文专题）。计划的存储只保存每次新增的部分，进入 SQLite，不再写成 blob。

## 对齐的判断

- **composer 是请求唯一的作者；内核只给事实、守保证、记录。** 按出厂 composer 现在用到的东西（几条宿主路径）设计输入，等于宿主替 composer 决定说什么。SillyTavern 式的 composer 要用角色卡、世界书与预设，宿主预料不到，也不该替它预料。所以分工是：
  - 内核与宿主给出只有它们有的事实，作为调用参数：Log 的投影（transcript 与上一份计划）、本 Round 的能力快照与不可用的插件、Session 要求常驻的救生集、回复与压缩的目标、安全模式及原因、带文件路径的图片引用、home 的路径、宿主采集的内容（常驻说明的原文与召回的记忆记录），以及宿主没能提供的内容和原因。图片存在 `.data` 下，那是库的内部位置，不是公开约定，所以路径由内核给出；composer 不做 I/O，所以常驻说明由宿主在每个 Round 开始时读一次，记忆由宿主召回。
  - 内核检查它承诺的保证：披露的能力来自本 Round，需要时救生集在场，Log 引用能解析，图片只发给接受图片的目标，压缩止于完整的 Round；然后记录。
  - 其余都归 composer：用不用、怎样用常驻说明与记忆，路径怎样写，系统提示与叙述，消息的顺序与角色，怎样改写历史（改写后的文字内联进计划），披露哪些工具，预算，何时压缩。路径由 composer 从 home 的路径出发，按契约写明的 home 布局拼出（WIT 中 `home` 字段的文档），与 Agent 用 shell 时依赖的是同一份约定。

  这些事实都按归属者自己的类型完整给出：Log 的投影用内核的类型，记忆用记忆的记录（core 的 `Memory`，逐字段），常驻说明就是 AGENTS.md 的原文，Session 给出 ID、名字、profile 与创建时间。不按出厂 composer 的用法挑选字段，也不装进通用的候选容器。按一个消费者裁剪的输入只适合那一个消费者：宿主路径的记录、只取 `instructions` 与带 `pinned` 的 `memories`，以及审阅中提议的"种类、ID、文字、是否常驻"的通用候选项，都是同一个错误。"是否常驻"是记忆召回里置顶与按输入召回的区分，抬成所有内容的属性，SillyTavern 式的 composer 就没有这个概念；实现中的候选项还把"这是记忆"同时存在种类与 ID 的 `memory:` 前缀里，转换层只能按字节切前缀。

  只在有访问边界时少给：扩展字段归写下它的 Provider，composer 只看到大小；Binding 是执行的内部状态。新的信息由它的归属者以自己的类型加入，在 core、内核端口与 WIT 各加一处，随第一个使用者增长；适配器完整解构两侧，不写通配分支，任何一侧新增字段或分支都编译不过，直到有人决定它怎样映射。召回要调嵌入与判断模型，不用记忆的 composer 拿到它是浪费；这样的 composer 出现时，再让它声明自己用哪些信息，宿主据此跳过采集，现在不预留。

  由此得出四点：
  - 上下文来源交出有类型的结果：常驻说明的原文、记忆记录与没能提供的内容。`Candidate` 与 `CandidateKind` 删除，`ContextSource` 留作宿主一侧采集的概念。
  - composer 只交出要披露的能力 ID，定义由内核从快照补上。"定义与快照相同"从检查变成结构，composer 也改不了定义。
  - 宿主没能提供的内容，由内核并入记录的计划，不靠 composer 转抄，所以"降级写进计划"仍由内核保证。
  - 计划不满足检查，是 composer 违反契约，记为 `plugin.contract`，进入健康门控，试用中的代际自动回退。

- **composer 是与 I/O 无关的纯函数：只看参数、配置与自己的制品，只交出返回值。** 提示词的组装本来就不需要 I/O。纯函数的确定性来自构造，契约测试只需构造参数；`.data` 的边界也不受影响：composer 没有文件可读，Log 只能经参数看到，而参数只给扩展字段的大小。

  要定的不是导入几个接口。2026-10-25 测量了一个 wasm32-wasip2 的最小 Rust 组件：代码只用了时钟与 `HashMap`，组件却导入了 16 个 WASI 接口（io、两个时钟、cli 的标准流、环境变量、退出、终端、`random/insecure-seed`），不给 WASI 就无法实例化，字面意义的"零导入"做不到。所以由宿主为每次调用配置 composer 的世界：
  - 与其他插件导入同一个 `host`，读配置、写日志；网络关闭，沿用 M28 给 probe 的 `Network::Closed`；
  - WASI 中没有预打开的目录，也没有环境变量；
  - 墙上时钟是本 Round 的时刻，单调时钟不走；随机数以 Round 的 ID 为种子。

  测量中，默认 WASI 下两个新 Store 的 `HashMap` 遍历顺序与时钟读数都不同，固定之后两次输出逐字相同。默认上下文中网络一律拒绝，去掉预打开的目录与环境变量之后，时钟与随机数是仅有的不确定来源。

  确定性因此是：同一个代际在同一个 Round 内，参数、选项与配置相同，计划就逐字相同。时刻不作参数，取时间只有时钟一条路；随机数按 Round 播种，不同 Round 之间照常变化。换 endpoint 之后，预算、图片能力与被跳过的候选都变了，参数不同，计划随之改变，这与确定性不矛盾。

  composer 自己专用的内容（角色卡、世界书、预设）放在它的插件目录里，构建时嵌进制品（例如 `include_str!`），随代际登记，所以能回退、能对比、有历史，"运行中的行为 ⟺ 已登记的代际"对它同样成立。代价是改一张角色卡要重新登记，构建只需几秒；运行时读 home 中的任意文件做不到。真有 composer 需要时，再加一个由它声明、宿主在 Round 开始时读取的来源，并且永远不读 `.data`。

  这是一条更一般的规则的实例：插件每次调用能看到什么，由宿主按它的角色给出。映射器的价值在于能在历史原文上重放，所以只看参数。probe 也是一例：`describe` 是唯一判断配置的地方，probe 只检查代码本身，所以没有网络，配置为空。M28 只关了它的网络，`host.config()` 仍返回主人的配置，与契约不符；六个出厂插件的 probe 都不读配置，本里程碑一并修正。

- **安全模式用 composer 插件的出厂代际，宿主不再有组装逻辑。** 出厂代际属于宿主，内嵌在二进制中、以空配置加载，Agent 替换不了它，"恢复不依赖被替换的东西"仍然成立；安全模式本来就依赖出厂的 Wasm Provider。保留原生实现，意味着同一套组装逻辑有两份，改出厂的措辞要改两处，两份迟早分歧。所以原生的 `FactoryComposer` 删除，出厂 composer 的源码与提示词移到 `plugins/composer`，Agent 取出后修改的就是宿主出厂的那一份。安全模式不读 profile 的选项，以空选项运行。插件专题与代际专题中"策略点改用原生实现"随之改写。

- **出厂插件的源码随宿主分发，取出就是接管。** 实现中，`enco init` 把 composer 的源码写进 `plugins/composer`，六个出厂插件里只有它带"放出源码"的标志。这改变了三件事：
  - 每个新 home 首次启动都要冷编译 composer（82 个 crate，含 chrono-tz），没有 Rust 工具链或构建失败时守护进程起不来；M29 之前，只有出厂插件的 home 启动不调用 cargo。
  - composer 成了主人的源码目录，宿主之后对出厂 composer 的修正一律收不到，违背代际专题「出厂代际属于宿主，跟随属于登记」。
  - 应用测试与评测测试都在 `init` 之后删掉这个目录，绕开构建，测试在改写产品行为。

  根源是计划写了"源码放进 home 的 `plugins/`"，默认了出厂插件的源码本来就在 home 里；实际上 M29 之前它们不在，`scaffold` 对已登记的名字报 `NameTaken`，也没有正式途径取出。改为：
  - 六个出厂插件的源码都随二进制分发，合计约 180 KB；`enco init` 不写出任何插件源码，home 中没有目录的出厂插件跟随宿主。
  - "需要修改"不由宿主判定，是主人或 Agent 的决定：对一个正在跟随出厂的名字执行 `scaffold`，起点就是它随宿主分发的源码，而不是工具插件的模板。取出就是接管：从下一次登记起它是普通的源码目录，不再跟随；删掉目录再登记，又回到跟随。这两条都是已有规则，取出只是给出入口。
  - 这条路对所有出厂插件相同，例如上游接口换代时，Agent 也能这样修 `openai-compatible`。
  - 取出之前读懂代码，需要出厂插件的导航手册；手册现在写着"源码不在 home，没有导航手册"。宿主构建时可以渲染它们，不在本里程碑；取出之后的第一次构建就会生成。

- **profile 选择 composer，并给出有类型的选项，选项在绑定处校验。** profile 写 `composer = { plugin = "…", options = { … } }`，不写时是出厂 composer 与空选项。出厂 composer 的身份只由宿主给出，经依赖交给内核，profile 的缺省与安全模式都按这个身份查找；内核不按插件名认识任何插件。实现中，内核在缺省值与安全模式两处写了字面量 `"composer"`，加上宿主的出厂清单，同一事实有三个来源。选项是调用参数，与 endpoint 的 `options` 同类，所以同一个 composer 代际可以被两个 profile 以不同的角色卡使用（插件专题「两种参数，按由谁选定区分」）。

  选项的类型不能写成 WIT 记录：宿主按一份固定的 world 编译，而每个 composer 的选项各不相同。工具参数是同样的情形，已经用 schema 解决，选项照此办理：composer 声明选项的 schema，用工具参数的同一个 JSON Schema 子集；SDK 从作者的 Rust 结构体生成它，调用时反序列化成同一个结构体，schema 与类型出自一处。

  只在登记时校验，保证不了实际用到的组合：profile 在 Round 开始时钉住，代码却在每次组装前选取，另一个 Session 的登记可能在 Round 中途换掉 composer 的代际；机械回退也可能让配置与代码不再匹配。所以 composer 这项使用由一个函数解析：输入 profile 的 composer 条目与注册表视图，输出实际运行的代际与按它的 schema 规范化的选项，或者这项使用为什么不可用。
  - 登记时在候选视图上求值，不合法就拒绝，错误指出 profile 与字段；
  - 每次组装前在当前视图上求值，不合法就是这项使用不可用：Round 失败，进入安全模式，原因写在状态里。配置与代码对不上不是代码本身的故障，不计入健康门控。

  这是代际专题「有意的命令守住接线，机械恢复只求回到能运行的状态」：同一项检查，结果按命令的性质处理。composer 收到的选项因此一定符合运行中代际的 schema，并已规范化（null 视为未给，5.0 读作 5）。空对象必须合法，与"空配置必须合法"是同一条规则；安全模式以出厂代际与空选项经同一个函数求值。endpoint 的 `options` 现在没有类型，以后可以用同一个机制，不在本里程碑。

- **每次组装传入整份输入。** 2026-10-25 测量：WIT 近似 `ComposeInput` 与 `ContextPlan`；组件是 wasm32-wasip2 的 Rust，构建参数与出厂插件相同；宿主是 wasmtime 49.0.1，配置照搬 enco-wasm（epoch 10 ms、异步导出、256 MiB 内存上限、每次调用一个新 Store）。数据取自 227 份评测 Log 的原始消息，按顺序重复；100 万 token 按 4.5 字节/token 折成 4.5 MB 文本，带 26 个真实的工具定义与上一份计划。组件内是简化的出厂组装逻辑，组出的计划与原生版本逐项相同。20 次的中位数：

  | 规模 | 条目 | 传入并返回计数 | 传入、组装并取回计划 | 原生组装 | 原生深拷贝 | 组件内存峰值 |
  |---|---|---|---|---|---|---|
  | 22.5 万 token（1.0 MB） | 1,063 | 0.65 ms | 0.88 ms | 0.11 ms | 0.15 ms | 2.5 MiB |
  | 100 万 token（4.5 MB） | 5,162 | 2.94 ms | 4.08 ms | 0.54 ms | 0.83 ms | 7.6 MiB |
  | 100 万 token，工具结果截到 200 字节 | 7,908 | 4.32 ms | 5.89 ms | 0.83 ms | 1.07 ms | 8.9 MiB |

  新建 Store 并实例化只要 0.03–0.05 ms。开销随条目数与字节数线性增长，主要花在跨边界复制上，约为原生"深拷贝加组装"的 3 倍，绝对值是几毫秒，而一次模型请求以秒计；内存峰值不到上限的 4%。所以每次组装传入整份输入，不提供按需读取 Log 的导入，也不做增量传入；安全模式的出厂 composer 也不需要单独放宽内存上限。

- **计划以完整内容的哈希为身份，存储只共享已经存过的部分**。"模型可见 ⟺ 已记录"要求每次 Attempt 先记下计划，现在每份计划都是一个完整的 blob，而默认 composer 只在末尾追加，所以每份计划都把上一份的全部内容再存一遍。单份计划受上下文预算约束，长期是线性增长，但常数是整份计划。2026-10-24 在 VPS 上只读测量了 25 天的真实使用：
  - blob 共 659 MB，数据库 10 MB；其中 97.6% 是计划。358 MB 是当前库引用的 1342 份计划，中位数 284 KB，约每天 14 MB；另有 296 MB 是迁移按新格式重写计划之后留下的旧 blob，已无人引用；图片、超长结果全文与制品合计约 4.4 MB。
  - 对 358 MB 当前计划：每份单独 zstd 为 155 MB（2.3×）；按字节公共前缀再 zstd 为 8.3 MB（43×，`tools` 排在 `items` 之后，每份都带着整个工具目录）；工具目录按内容共享、条目以上一份为父再 zstd 为 4.3 MB（82×）；对上一份做 zstd 差分为 2.7 MB（133×）。工具目录中位 7.3 KB，全程只有 8 种；最长的一个系列有 203 份计划。

  所以冗余在计划之间，单份压缩只是补充。存储改为：
  - 工具目录按内容存为一个对象，计划记录只引用它；
  - 新计划的条目以本 Session 上一份计划的全部条目开头时，记为"上一份计划 + 新追加的条目"，否则记全量；还原链设上限，到上限也记全量，使还原的代价有界；
  - 每条记录以 zstd 压缩，写进 SQLite，与引用它的 AttemptStarted 在同一个事务中提交。先写 blob 再提交的两步之间崩溃会留下孤儿；同一个事务让它从结构上不可能出现，也就是"写入与接纳事实一起原子提交"。

  是否增量只由前后两份计划比较得出，不看计划出自哪个 composer：默认 composer 开始新系列时，以及重排历史的组装方式（例如 SillyTavern 式的），都自然走全量。按 composer 的身份分支，正是双向不泄露所拒绝的结构。

  这是 Store 内部的存储编码，身份与表示分开，与 LayerFS 的做法相同。Log 中记的仍是完整计划的哈希；检视、重试与下一次组装读到的总是完整计划，还原后按哈希核对，链上任何一环缺失都直接报错。所以"记录的就是模型看到的"不变，composer 的契约也不变。它每轮重复的内联内容（如角色卡、世界书）测出问题时，再像工具目录一样按内容共享。
- **路径会交出去的 blob 保持原样**。图片、超长结果的全文与发给主人的文件，以文件路径交给 Agent 与主人读取，压缩后按路径读到的就是乱码；它们本来也不大，图片已经是压缩格式。所以只有计划这类从不交出路径的内部记录换存储编码。
- **不做 blob 回收；构建日志移出 blob 库。** 回收的需求来自计划：VPS 上 97.6% 的 blob 是计划。计划存进 SQLite 之后不再产生计划 blob；已有的 654 MB（358 MB 在用、296 MB 早已无人引用）在主人升级库、重新编码之后全部无人引用，要删哪些从旧库与 blob 的内容就能查出，由主人一次删除。其余内容增长很小：图片、超长结果全文与制品 25 天合计约 4.4 MB。

  回收本身是一条全局不变式。Log、Inbox、登记、配置代际与手册表都持有 blob 引用，源码与手册还是沿清单展开的树；以后每个新的持有者（记忆中的图片、插件状态、P4 的跨节点复制）都必须加入引用根，漏一处，回收就会悄悄删掉已接纳的内容，而且很晚才发现。这份计划的审阅中就漏了 Inbox 与手册两处。P4 中 blob 按哈希在节点之间分发，单机的回收届时也要重新设计。所以本里程碑不做回收，回收与保留策略一起设计（路线图"之后"），届时连同 P4 的分发。

  构建日志是构建的副产品，不是被记录引用的事实，只以路径出现在结果文字里，所以不进内容寻址的库，改写在构建目录 `.data/target/` 下。构建目录本身就是可以删掉重建的派生物，体积大几个数量级；M28 的试跑中日志每份 60–124 KiB，每道题 1–3 份。日志保留到构建目录被清理，结果文字写明这一点。这样"每个 blob 都有记录引用"成立，只有崩溃时留下的少量孤儿例外，以后设计保留策略也更简单。

  新库建表时开启 `auto_vacuum = INCREMENTAL`，以后计划记录有了保留策略，删除之后可以逐步把空间还给文件系统，不必重写整个库；它只在建库时能设，事后开启要做一次 `VACUUM`。

## 范围

- **composer 的 WIT**：新增 `composer` 接口与 `composer-plugin` world，草案见下文；已有接口不变。
- **出厂 composer**：原生的 `FactoryComposer` 连同提示词移为出厂插件 `plugins/composer`，像其他出厂插件一样嵌进二进制。路径按 WIT 写明的 home 布局拼出；图片过大的叙述不写具体上限，上限只由内核持有，插件里不再有它的副本。
- **出厂源码**：六个出厂插件的源码都随二进制分发，`enco init` 不写出任何插件源码；`scaffold` 一个正在跟随出厂的名字，写出它随宿主分发的源码。只给 composer 的"放出源码"标志删除。
- **内核**：
  - `Composer` 端口改为异步，由 enco-wasm 的适配器实现；每次组装前从注册表视图解析 composer 这项使用（见对齐的判断），安全模式解析为出厂代际与空选项；`KernelDeps.composer` 删除。
  - 出厂 composer 的身份经依赖由宿主交给内核，profile 的缺省与安全模式都按它查找，内核里没有插件名的字面量。
  - 端口的输入与 WIT 逐字段对应：去掉 `image_paths`（路径并入图片引用），增加救生集与 home 的路径；上下文来源交出有类型的结果（常驻说明的原文、core 的 `Memory` 记录、没能提供的内容），`Candidate` 与 `CandidateKind` 删除；Session 给出 ID、名字、profile 与创建时间；Round 的时刻与 ID 只用来配置 composer 的 WASI，不进 WIT 的参数。
  - 计划中的工具只收能力 ID，定义由内核从快照补上；宿主的省略由内核并入记录的计划。
  - 计划校验失败记为 `plugin.contract`，`Verdict` 的文档随之改写；composer 返回的失败除 `context.overflow` 外，一律记为 `compose.failed`。
  - `AttemptStarted.composer` 记录 composer 的代际 ID。
- **enco-wasm**：每次调用按角色给出插件能看到的世界：
  - composer：网络关闭；WASI 中没有预打开的目录与环境变量，时钟与随机数取自 Round；另有 composer 的绑定与类型转换，转换完整解构内核与 WIT 两侧，不写通配分支；
  - 声明（`describe`、工具定义、composer 的选项 schema）：网络关闭，配置照常；
  - probe：网络关闭，`host.config()` 返回 `{}`；
  - 其余调用照旧。
- **配置**：profile 的 `composer` 字段；登记时与每次组装前用同一个函数解析 composer 这项使用，它调用运行中代际的 `options-schema`。
- **SDK**：composer world 的导出宏、从选项类型生成 schema 与反序列化、计算来源哈希的函数。
- **测试**：enco-host 的 kernel、continuity、images 集成测试改用端口上的测试 composer，只测内核的机制；组装行为的测试移进 `plugins/composer` 自己的测试（`cargo xtask check` 已经在本机运行插件测试）；apps/enco 的端到端测试运行真实的 Wasm composer。应用测试与评测测试中 `init` 之后删除 `plugins/composer` 的绕行随出厂源码的改法删除。
- 挂在 composer 名下的事项（稳定性标注、按空闲时长开始新系列、缓存友好的披露策略）由 Agent 在评测下迭代，不作为本里程碑的验收条件。
- **计划的存储**（见对齐的判断）：
  - 工具目录按内容存为对象；
  - 记录计划时与本 Session 上一份计划比较，决定记增量还是全量；还原链的上限按还原耗时测定；
  - 记录以 zstd 压缩（引入 `zstd` crate），存进 SQLite，与 AttemptStarted 同一个事务提交；计划不再写成 blob；
  - 还原时沿父链走到最近的全量记录，再按哈希核对；
  - 计划记录以后的保留沿父链计算，本里程碑不删除计划记录。
- **构建日志**：写在 `.data/target/` 下，不进 blob 库；结果文字写明它保留到构建目录被清理。新库开启 `auto_vacuum = INCREMENTAL`。
- **库的升级**：库的版本随计划的存储升级。oracle-jp 上的库由主人手动升级，重新编码计划之后，不再有引用的旧计划 blob 也由主人删除。
- **评测**：运行器与题目在 Enco 仓库中，不在 `ENCO_HOME`。变体给出插件的源码目录，在试跑中经正式路径构建，被评测的就是之后登记的同一份源码；`enco plugin deploy <name> <path>` 删除。Agent 在工作区取得与宿主版本对应的仓库（`enco --version` 写着提交），把自己的 composer 作为被测的代际。评测用被测模型与评判模型的 key，由主人运行。默认变体运行出厂 composer，试跑中不从源码构建它。运行器的内容哈希只作变体的身份，不声称与 Enco 的源码树是同一约定；插件名是否合法由宿主判断，运行器不复制它的语法，只检查它是 `plugins/` 下的单个目录名：写入源码之前要先删除同名目录，这条边界只有运行器自己守得住。主人文档与评测 README 随代码一起改。
- **留出集推迟**：验证专题要求 Agent 开始对着任务集自我进化时，把留出集放到它够不着的地方。本里程碑只演示一轮迭代，谈不上记住答案，所以推迟到 Agent 开始反复迭代时，那时留出集放到另一个节点或另一个系统用户下。

## 设计

验收时提炼或改写：

- 上下文专题「正确性在内核，策略在 composer，线上格式在 Provider」：改写为 composer 是请求唯一的作者、与 I/O 无关的纯函数，内核给事实、守保证、记录；事实按归属者的类型完整给出，不按消费者裁剪，也不装进通用容器，落点是两侧完整解构的转换。「composer 是每个 Session 的属性」：补上 profile 的选项与它的类型，选项在绑定处校验；删去"Context 贡献只用一小组共享的种类描述候选"。
- 记忆专题「内核不知道记忆」改为「内核只转交记忆的记录，不知道它怎样存储与召回」；总纲的固定词去掉 Candidate。
- 代际专题「出厂代际属于宿主，跟随属于登记」：补上出厂源码随宿主分发、取出就是接管、删掉目录回到跟随。
- 插件专题新增"插件每次调用能看到什么，由宿主按它的角色给出"：composer 看参数、配置与 Round 的时钟和种子，映射器只看参数，probe 没有网络、配置为空。「外部只经映射器进入，映射器不做 I/O」中"不带任何导入的组件"随之改写。
- 插件专题「扩展点只有 Observer 与少数几个策略点」「原生能力与插件经同一组端口接入，救生集始终有原生实现」，代际专题「安全模式是开关与本 Run 的 Log 的函数」：安全模式的策略点改用出厂代码，策略点由插件实现时就是它的出厂代际。
- Session 专题「Round 开始时钉住所见，Attempt 开始时选取代码」：composer 与 Provider 一样在每次组装前选取代码，钉住的选项与选出的代际在选取时一起校验。
- Session 专题「Log 只记事实的骨架」与「请求只有一个构造者，记录之后只解析记录」：计划不再存为 blob，而是库中按结构共享的记录；"记录保留多久是主人的策略"同时作用于计划记录与 blob，Enco 目前不自动回收。
- "计划以完整内容的哈希为身份，存储只共享已经存过的部分"是否提炼，候选位置是上下文专题「叙述逐字冻结在计划中」之后。
- 验证专题「优先使用能覆盖行为的最高一层」：集成测试中不再有出厂 composer。
- 总纲的源码地图：出厂 composer 并入出厂插件一行，宿主一行去掉 composer。
- 先定下的格式：composer 的 WIT（见下文）；计划记录与工具目录的表、记录的编码（增量或全量、zstd）；库的版本随之升级，新库开启渐进回收。

## composer 的 WIT（草案）

每项输入都是某个归属者的事实，按它自己的类型完整给出（见对齐的判断）：`memory` 与 core 的 `Memory` 逐字段对应，`session` 给出 Session 记录中除 Binding 以外的事实，`home` 的文档写明 home 的布局。composer 看到的是 Log 中的记录，与 Provider 收到的请求不同：图片是引用，适配器字段只给大小（宿主只把它交给写下它的插件），工具调用带 Enco 的调用 ID。所以消息类型在 `composer` 接口内单独定义，`types.message` 不变。只新增接口与 world，已有接口不变；版本号以已有组件不必重建为准，实现时按 wasmtime 的链接规则核对。

```wit
/// Writes the model requests of the Sessions whose profile names this plugin.
///
/// A composition is a pure function of its arguments, the plugin's configuration and its own code,
/// and changes nothing but its result: it has no files, no environment variables and no network, so
/// `host.http` fails. The wall clock reads the Round's instant, the monotonic clock stands still and
/// randomness is seeded by the Round, so the same generation, called again within a Round with the
/// same arguments, returns the same plan.
///
/// The host records each plan before sending it and resolves its Log references. A plan breaks
/// this contract when it discloses a capability outside this Round, refers to a position outside
/// the transcript, or sends images to a model that does not accept them; when a reply plan leaves
/// out a capability in `lifeline`; or when a compaction discloses any tool or stops where no Round
/// ends.
interface composer {
    use types.{failure, image-format, json, role, tool-spec};

    /// A UTC instant, shaped like `wasi:clocks/wall-clock.datetime`.
    record datetime {
        /// Seconds since the Unix epoch.
        seconds: u64,
        /// Nanoseconds past `seconds`.
        nanoseconds: u32,
    }

    /// The position of an entry in this Session's Log.
    record log-pos {
        /// The ownership epoch that wrote the entry; 1 on a single node.
        epoch: u64,
        /// The entry's place within its epoch.
        seq: u64,
    }

    /// The Session the request is for.
    record session {
        /// Its permanent ID.
        id: string,
        /// Its unique name, as the owner's commands use it.
        name: string,
        /// The profile it uses, by name.
        profile: string,
        /// When it was created.
        created-at: datetime,
    }

    /// A recorded image, by reference rather than by its bytes.
    record image-ref {
        /// How the bytes are encoded.
        format: image-format,
        /// The size of the bytes.
        size: u64,
        /// The BLAKE3 digest of the bytes, in lowercase hex.
        content: string,
        /// The file that holds the bytes.
        path: string,
    }

    /// A tool call that a reply proposed.
    record call {
        /// Enco's ID for the call, which its result repeats.
        id: string,
        /// The tool called.
        name: string,
        /// The arguments as the model wrote them, as JSON text.
        arguments: string,
    }

    /// What the model read as the result of a call.
    record call-result {
        /// The `id` of the call.
        call-id: string,
        /// The result text.
        content: string,
        /// Whether the call failed.
        is-error: bool,
    }

    /// One piece of a recorded message.
    variant part {
        /// Text.
        text(string),
        /// A proposed tool call.
        tool-call(call),
        /// The result of a call.
        tool-result(call-result),
        /// The size in bytes of adapter fields, which the host gives only to the plugin that wrote
        /// them.
        extension(u64),
        /// An image.
        image(image-ref),
    }

    /// A message as the Log records it.
    record message {
        /// Who speaks.
        role: role,
        /// The content, in order.
        parts: list<part>,
    }

    /// The channel conversation an input came from.
    record channel-source {
        /// The protocol, as the channel adapter names it.
        channel: string,
        /// The account within the protocol.
        account: string,
        /// The conversation that replies return to.
        conversation: string,
        /// The authenticated sender.
        sender: string,
    }

    /// Who produced an input.
    variant event-source {
        /// The owner, through Enco's own interface.
        cli,
        /// Someone in a channel conversation.
        channel(channel-source),
        /// A schedule.
        scheduler,
        /// The plugin registry, after an automatic rollback.
        registry,
    }

    /// Why an attachment did not become an image.
    variant unviewable-reason {
        /// Its format is not an accepted image format.
        unsupported,
        /// It is larger than an image may be.
        too-large,
        /// It could not be retrieved, for this reason.
        unavailable(string),
    }

    /// An attachment kept only as a description.
    record unviewable {
        /// The channel's description of it.
        what: string,
        /// Why it is not an image.
        reason: unviewable-reason,
    }

    /// A message from the owner.
    record user-message {
        /// What the owner wrote.
        text: string,
        /// The images sent with it.
        images: list<image-ref>,
        /// The attachments that are not images.
        unviewable: list<unviewable>,
    }

    /// A schedule reaching its time.
    record reminder {
        /// The schedule's ID.
        schedule: string,
        /// When this occurrence was due.
        due-at: datetime,
        /// Earlier occurrences that were missed and not delivered.
        skipped: u32,
        /// The reminder text.
        text: string,
    }

    /// A trial generation that failed, and what runs instead.
    record rollback {
        /// The plugin, by name.
        plugin: string,
        /// The failed trial generation.
        trial: u64,
        /// The generation running now; absent when none is healthy.
        replacement: option<u64>,
        /// The fault that caused the rollback.
        failure: failure,
        /// The notice the registry wrote.
        text: string,
    }

    /// What an input says.
    variant event-body {
        /// A message from the owner.
        user-message(user-message),
        /// A scheduled reminder.
        reminder(reminder),
        /// A notice of an automatic rollback.
        generation-rolled-back(rollback),
    }

    /// An input this Session consumed.
    record event {
        /// Its ID.
        id: string,
        /// When it arrived.
        received-at: datetime,
        /// Who produced it.
        source: event-source,
        /// What it says.
        body: event-body,
    }

    /// How a Run ended.
    variant run-end {
        /// It finished.
        completed,
        /// It used every Round it was allowed.
        budget-exhausted,
        /// The process stopped before it finished.
        interrupted,
        /// It was cancelled.
        cancelled,
        /// It failed.
        failed(failure),
    }

    /// A Run's end, and where the Log records it.
    record run-ended {
        /// The entry that records the end.
        pos: log-pos,
        /// How the Run ended.
        end: run-end,
    }

    /// A message the Log records, with the input it came from.
    record transcript-item {
        /// Where the Log records it.
        pos: log-pos,
        /// The message.
        message: message,
        /// The input it records; absent for replies and tool results.
        event: option<event>,
    }

    /// The history a plan may refer to.
    record transcript {
        /// The latest summary, which replaces the history before it.
        summary: option<string>,
        /// The messages after that summary, in Log order.
        items: list<transcript-item>,
        /// The ends of complete Rounds, where a compaction may stop, in Log order.
        round-ends: list<log-pos>,
        /// How each Run after the summary ended, in Log order.
        run-ends: list<run-ended>,
    }

    /// A durable fact about the owner, as the memory records hold it.
    record memory {
        /// Its identity, kept through corrections; the memory tools take it.
        id: string,
        /// The current statement.
        text: string,
        /// Whether it is offered every Round regardless of the input.
        pinned: bool,
        /// When it was created.
        created-at: datetime,
        /// When it was last changed.
        updated-at: datetime,
        /// Starts at one and grows with each correction.
        rev: u64,
    }

    /// Content left out of a request, and why.
    record omission {
        /// What was left out, such as `memory:<id>`.
        source: string,
        /// Why, for whoever inspects the request.
        reason: string,
    }

    /// A tool's identity, qualified by the node that provides it.
    record capability-id {
        /// The node that provides the tool.
        node: string,
        /// The tool's name, unique within a Round.
        name: string,
    }

    /// A tool this Round may disclose.
    record capability {
        /// The identity a plan discloses it by.
        id: capability-id,
        /// The definition the host records with a plan that discloses it.
        spec: tool-spec,
    }

    /// A plugin left out of this Round.
    record unavailable-plugin {
        /// The plugin, by name.
        plugin: string,
        /// Why it is left out.
        failure: failure,
    }

    /// Why this Round runs in safe mode.
    variant safe-mode {
        /// The owner turned safe mode on.
        owner,
        /// This Run failed against the generations that are still running.
        failed(failure),
    }

    /// A model's limits.
    record budget {
        /// The context window, output included.
        context-tokens: u32,
        /// The most tokens a reply may use.
        max-output-tokens: u32,
    }

    /// Input other than text that a model accepts.
    enum modality {
        /// Images.
        image,
    }

    /// A reply endpoint passed over, and why.
    record skipped-endpoint {
        /// The endpoint, by its configured name.
        endpoint: string,
        /// Why it was passed over.
        failure: failure,
    }

    /// The model a reply plan is for.
    record reply-target {
        /// Its limits.
        budget: budget,
        /// What it accepts besides text.
        accepts: list<modality>,
        /// Earlier candidates that are unavailable or exhausted in this Run, in configured order.
        skipped: list<skipped-endpoint>,
    }

    /// Everything the host supplies for one composition.
    record compose-input {
        /// The Session the request is for.
        session: session,
        /// The owner's time zone, as an IANA name such as `Asia/Shanghai`.
        timezone: string,
        /// The home's absolute path on the node running this Round.
        ///
        /// Its layout is part of this contract: `config.toml`, `AGENTS.md` for the standing
        /// instructions, `plugins/<name>/`, `sdk/`, `manual/` and `workspace/`. `.data/` is Enco's
        /// own store and not part of it.
        home: string,
        /// The history a plan may refer to.
        transcript: transcript,
        /// This Session's latest reply plan, as it was returned; absent at the start, or when it
        /// could not be read, which `omitted` then says.
        previous: option<plan>,
        /// The text of `AGENTS.md`, as read at the start of this Round; absent when the file does
        /// not exist, and in safe mode.
        instructions: option<string>,
        /// Memories for this Round in priority order: pinned ones first, then those recalled for
        /// the latest input, most relevant first; empty in safe mode.
        memories: list<memory>,
        /// Content the host could not supply; the host records it with the plan.
        omitted: list<omission>,
        /// Every tool this Round may disclose; in safe mode, only the lifeline.
        capabilities: list<capability>,
        /// The tools every reply plan must disclose; empty when the Session does not require the
        /// lifeline.
        lifeline: list<capability-id>,
        /// Plugins left out of this Round.
        unavailable: list<unavailable-plugin>,
        /// Why this Round runs in safe mode; absent in normal operation.
        safe-mode: option<safe-mode>,
        /// The model a reply plan is for.
        reply: reply-target,
        /// The summarizing model's limits; absent when no summarizing model is usable.
        compaction: option<budget>,
        /// How many more compactions this Round allows.
        compactions-left: u32,
    }

    /// A source a plan renders, with a digest a later composition can compare.
    record source {
        /// The source, such as `memory:<id>`.
        id: string,
        /// The BLAKE3 digest of its text before formatting, in lowercase hex.
        hash: string,
    }

    /// Text the composer wrote, recorded verbatim.
    record inline {
        /// Who speaks.
        role: role,
        /// The text.
        text: string,
        /// The sources it renders, in order.
        sources: list<source>,
    }

    /// A Log message the request repeats.
    record log-ref {
        /// The message, by its position in the transcript.
        pos: log-pos,
        /// Whether its images go with it; all of them or none.
        images: bool,
    }

    /// One message of a request.
    variant plan-item {
        /// Text the composer wrote.
        message(inline),
        /// A message from the Log.
        log(log-ref),
    }

    /// A request, before the host records and resolves it.
    record plan {
        /// The messages, in order.
        items: list<plan-item>,
        /// The tools to disclose, by identity.
        tools: list<capability-id>,
        /// The most tokens the reply may use; the service's default when absent.
        max-output-tokens: option<u32>,
        /// What the composer left out, and why.
        omitted: list<omission>,
    }

    /// A request to summarize history before replying.
    record compaction {
        /// The last Round end to summarize, one of `transcript.round-ends`.
        upto: log-pos,
        /// The summarizing request; it discloses no tools.
        plan: plan,
    }

    /// What a composition returns.
    variant composition {
        /// A reply request.
        reply(plan),
        /// Summarize history first; the host composes again once the summary is recorded.
        compact(compaction),
    }

    /// The JSON Schema of the options a profile passes to `compose`, in the subset `tool-spec`
    /// states.
    ///
    /// An empty object must fit it. The host checks a profile's options against the schema of the
    /// generation that runs them: registering configuration or code that breaks a profile's options
    /// is rejected, and a profile whose options no longer fit, as after a rollback, cannot use this
    /// plugin until they do. The schema is fixed with the generation, so this runs without network
    /// access.
    options-schema: func(config: json) -> json;

    /// Write the next request.
    ///
    /// `options` fit the running generation's `options-schema` and are normalized as tool arguments
    /// are. Return `compact` only while `compaction` is present and `compactions-left` is above
    /// zero.
    ///
    /// # Errors
    /// `context.overflow` when no valid request fits the window; when only a compaction would make
    /// it fit and `compaction` is absent, the host records why no summarizing model is usable. The
    /// host records any other code as `compose.failed`.
    compose: func(options: json, input: compose-input) -> result<composition, failure>;
}

/// A plugin that writes model requests.
world composer-plugin {
    include base;
    export composer;
}
```

## 验收

- 部署一个改坏了披露策略的 composer 代际之后，仍能调用文件、Shell 与部署管理，并经正式路径回退：计划不满足声明的要求时按 composer 违反契约处理，试用中的代际自动回退；Round 失败后进入安全模式（M22），安全模式用出厂 composer。
- composer 的世界：
  - composer 中读文件、读环境变量与发 HTTP 都失败，原因可读；
  - 同一个代际在同一个 Round 内，参数、选项与配置相同，调用两次得到逐字相同的计划，即使 composer 读了时钟与随机数；宿主一侧由 WASI 的边界测试保证，真实组件做一次手动核对；
  - 换到不接受图片的 endpoint 后重新组装，计划去掉了图片，并通过内核的检查；
  - 修改 AGENTS.md 之后，下一个 Round 的计划逐字包含新的内容。
- profile 的选项：
  - 不符合 composer 的 schema 时登记被拒绝，并指出 profile 与字段；登记的新 composer 代际使已有 profile 的选项不合法时，同样被拒绝；
  - 一个 Round 进行中，另一次登记换了 composer 的代际与选项，这个 Round 下一次组装时，按当时运行的代际校验本 Round 钉住的选项；机械回退使选项不再合法时，这项使用不可用，Round 失败并进入安全模式，状态写明原因；
  - 安全模式以出厂代际与空选项运行。
- probe 中 `host.config()` 返回空对象，与登记的配置无关。
- 出厂源码：
  - 新建的 home 不需要 Rust 工具链就能启动并对话，默认 composer 跟随出厂；
  - `scaffold composer` 写出它随宿主分发的源码；修改并登记之后，它不再跟随宿主；删掉目录再登记，回到跟随出厂。
- 计划的存储：
  - 默认 composer 连续运行若干 Round，每个 Round 新增的存储只与新追加的条目成正比；
  - 工具目录不变时，每个工具定义只存一份；
  - 不是追加形态的计划存全量；
  - 重启之后，任何一份计划还原出的内容都与记录的哈希一致；
  - 计划记录与 AttemptStarted 同一事务提交，在两者之间注入故障，不留下任何计划记录；
  - 还原链达到上限时记全量，任何一份计划的还原步数不超过上限。
- 构建日志写在构建目录下，不进 blob 库；结果文字中的路径读得到这次构建的日志。
- 手动核对：主人升级 oracle-jp 上的库、重新编码真实历史之后，计划的总存储与测量的估计（约 4 MB）同一量级；旧的计划 blob 随后由主人删除。
- 以 Wasm composer 运行的已有评测题，按 `evals/README.md` 的判定规则不低于 M28 宿主的原生 composer。
- Agent 取出出厂 composer 的源码，修改并登记，在已有题目上以出厂 composer 为 base、修改后的为 candidate 运行一次 `compare`，结果写入运行记录。验收看这个闭环能走通，不要求成绩更好。

### 审阅后的修订（2026-10-25）

实现审阅（内核、注册表、enco-wasm 与存储逐文件阅读，出厂 composer、SDK 与评测运行器由子代理审阅后逐条核对）确认整体结构符合计划：选项在登记与组装时经同一个绑定函数校验；计划只交能力 ID，定义由内核补上；计划与 Attempt 同一事务提交，`log.plan` 以外键指向计划记录；`CallWorld` 按调用的角色给出网络、配置与时钟；出厂组装逻辑忠实移植。下列几处与主人重新对齐，判断已写入上文，代码已随之修改：

- 出厂源码不再预先写进 home，`scaffold` 一个跟随出厂的名字时取出它；见「出厂插件的源码随宿主分发，取出就是接管」。
- composer 的输入按归属者的类型完整给出：上下文来源交出常驻说明的原文与 core 的 `Memory` 记录，`Candidate` 删除，转换完整解构两侧；见「composer 是请求唯一的作者」。
- 出厂 composer 的身份由宿主经依赖交给内核，内核里不再有插件名的字面量。
- home 布局写进 WIT 中 `home` 字段的文档，成为 composer 拼路径的唯一依据；图片过大的叙述不写具体上限，插件里的上限副本删除。
- 评测运行器不再声称内容哈希与 Enco 的源码树同一约定，也不复制插件名的语法。
- 删除实施中加入的接纳条件 `candidates.contains(usage.plugin())`。它让同一插件下已经坏掉的接线拦住局部修复，违背 `accept_change` 文档写明的"旧故障照常报告，不阻塞局部修复"；原有的两个条件已经拒绝新代码破坏原本有效的使用。另加测试锁住：机械回退让 profile 的选项失配之后，登记同一插件的其他代码仍被接受，失配照常报告。
- 运行器删除插件名语法的副本，改为只检查目标是 `plugins/` 下的单个目录名。
- 子代理报告的较小问题：插件的 token 估算改为按文本字节加固定开销，SDK 不再为生成类型派生 `serde::Serialize`，恢复说明中的失败对象显式写出；去掉解析之后被丢弃的选项；补回几条不变式的理由注释；两处断言措辞的测试改为断言行为。三个测试 Runtime 各自加载出厂 composer 的分支保留：统一包装会覆盖刻意以同一字节注入特定 composer 的测试。

独立审阅（一个子代理只读审阅全部改动，结论逐条对照代码核实）之后，又与主人对齐并修改了下列几处：

- 声明调用不能联网。`describe`、工具定义与 composer 的选项 schema 随代际固定，每次加载都重新求出。网络开着时，同一个代际会随外部变化声明出不同的内容，重启与回退也要依赖网络，「外部的契约先写成定本」只能靠插件自觉。它们改在关闭网络的调用世界中运行，插件专题「调用的角色决定它能看到的世界」与 WIT 文档随之改写；登记配置时对新使用的真实调用照常联网。
- 「直接制品」删除。deploy 删除之后它已没有生产者，`Origin`、`CodeSource` 与登记历史中的对应分支、存储中的 `artifact` 来源与展示分支一并删除。主人升级 oracle-jp 的库时，旧历史中若有这类记录，需要在升级时处理。
- 转换的完整解构补到插件到内核的方向与事件投影；角色、图片格式与 effect 的映射收为 `convert.rs` 中的 `From` 实现，Provider 与 composer 共用。
- 出厂源码的嵌入白名单由 scaffold 的测试核对：按宿主的源码规则读取仓库中的目录与取出的目录，比较整棵树。
- 计划的身份由 core 的 `ContextPlan::hash` 一处给出；`AttemptStarted` 的 composer 收紧为代际 ID；WIT 写明安全模式下没有常驻说明与记忆；其余是措辞、过时的注释，以及一处断言常量的测试。
