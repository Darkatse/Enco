# M21 自我修改只有一条路径

> 路线图 P2 的第 3 个里程碑。计划的生命周期见 spec 09 §5。

## 目标

实现总纲 §1.3 的第二个不变式：插件代码、插件设置、接线与内核配置都先经校验登记为代际，由注册表一个提交者生效、回退与恢复；重启只恢复，不读取新的意图。机制见 §4.5、§4.11。

## 范围

- **两种代际**：
  - 插件代际 = 制品 + `[plugin.<名字>]` 整节（`config` 交给插件，`secrets` 只由宿主读取）；
  - 配置代际 = 不属于任何插件的设置，包括 endpoint 的 `api_key_env`。
- **应用配置**：`enco config apply` 与工具 `config_apply` 同源。
  - 跳过与活跃代际相同的部分，其余按目标状态整体校验：加载、`describe`、probe、准入，以及对改变了的 endpoint 各做一次真实的最小调用。
  - Session 选用的 profile 也是接线：删掉或改名一个仍有 Session 在用的 profile，整次拒绝并列出这些 Session（§4.10 第 3 条）。回退仍可以拆掉它，那时由 `profile.unknown` 报出。
  - 校验通过后，一次应用就是注册表的一次提交。
- **登记携带期望的活跃代际**：部署与应用配置都一样，提交时任何一项不一致就整次拒绝。删除 spec 11 §5 给部署的豁免（它以"部署不继承任何东西"为前提，代际包含设置之后不再成立），A34 改为后提交者被拒绝。
- **重启只恢复活跃代际。**
  - `serve` 启动时，`config.toml` 与生效中的配置不一致，或者文件无法解析，都在日志中警告。
  - 首次启动（包括第一次以新版本启动的现有 home）把 `config.toml` 登记为第一批代际，直接为健康。
- **生效时机**：
  - Round 开始时钉住配置；
  - 时区变化时，Scheduler 立即重新推算；
  - embedding 与渠道的变化，第一版报告需要重启。
- **回退**：配置代际登记即为健康。回退配置是原生管理入口的机械恢复（`enco config rollback`，§4.6），不作为 Agent 的工具：Agent 撤销配置就是把 `config.toml` 改回去再应用，两者因此保持一致。插件的回退仍是 `plugin_rollback`。
- **`enco status`**：区分"`config.toml` 有从未登记的修改"与"已登记为代际 N 并被回退，原因是……"。
- **出厂代际**（§4.5）：当前二进制的出厂制品 + `{}`。宿主升级时是否跟随按制品判断：活跃代际运行出厂制品的插件，以新制品与生效中的设置走一次部署。跟随产生的代际先于新的出厂代际登记，试用失败时回到原来带设置的代际。

## 规格

- 03：插件代际记录全部设置；配置代际的存储；schema 加一。
- 04 §6：配置在 Round 开始时钉住。
- 06：embedding 的变化（第一版需要重启）。
- 08 §1、§3、§4：`enco config apply` 与 `enco config rollback`；`[plugin.<名字>.config]` 与 `[plugin.<名字>.secrets]` 的格式；首次启动登记配置、之后重启只恢复并在不一致时警告；不再因配置无效拒绝启动（全新的 home 除外）。
- 11 §1、§3、§4.1、§5、§8：配置代际；出厂代际与升级跟随；登记流程的两个入口；一次应用一次提交；删除部署的豁免与 A34 的改动；status 的两种不一致。
- 12：profile 与 endpoint 经应用配置生效；删除在用的 profile 被拒绝。

## 验收

- 把 endpoint 的模型名改成不存在的名字，执行应用配置：整次被拒绝，不登记任何代际，错误指出是哪个 endpoint。
- 删掉一个仍有 Session 在用的 profile，执行应用配置：整次被拒绝，错误列出这些 Session；用 `enco profile` 把它们切走之后重新应用，成功。
- 应用配置修改了 profile：下一个 Round 用新的 profile，不需要重启。正在进行的 Round 不受影响。
- 改了 `config.toml` 但没有应用，直接重启：活跃代际不变，日志里有警告。把 `config.toml` 写坏后重启：节点照常启动。
- 应用配置校验期间，同一插件被部署了新代际：应用配置被拒绝，什么都不写；重新应用后成功。
- 同一次应用里，既加了某个插件的密钥映射，又启用了需要它的设置：准入按最终状态通过。
- 宿主换一份出厂字节启动：只改过设置的插件跟随到新制品并保留设置；主人部署过自己代码的插件不变；安全模式使用的出厂代际设置为 `{}`。
- `enco config rollback` 回到上一个配置代际：`enco status` 说明被回退的原因，并报出 `config.toml` 与活跃代际不一致。
