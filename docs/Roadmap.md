# Enco 路线图

路线图按验收标准划分阶段。设计见[设计文档](design/README.md)，文中的"某某专题"指其中的专题。已完成的阶段（P0、原生 Telegram 渠道、P1、周期定时）与里程碑（M1–M25）的验收记录在 git 历史中。

**计划的生命周期。** 阶段开始时，路线图写阶段目标与里程碑顺序，每个里程碑一份计划放在 [plan/](plan/)：目标、对齐的判断、范围、设计（要新增或改写的设计条目）、验收与待定。里程碑开始时计划定稿；新的 WIT、数据库模式这类需要先定下的契约写在计划里，实现之后以代码为准。验收场景逐条写进计划，实现中的偏离与手动核对记录也写进计划。验收通过后，对齐的判断中长期有效、决定系统性质的提炼进设计文档；本里程碑返工过的地方写进 [LESSONS.md](../LESSONS.md)，见到三次的教训斟酌提升，提升后删除；仍有效的暂不实现移入路线图或后续计划；计划原文连同手动核对记录与真实运行数据移入本地的 `.archived_docs/plan/`，不进仓库，验收提交的说明写明实现了什么。

**里程碑的完成条件。** 验收场景通过，`cargo xtask check` 通过，逐路径审阅之后由主人从第一性原理审核通过；偏离计划的决定已经说明理由并得到主人确认。里程碑结束时系统完整可用，过渡形态只存在于代码中。

| 阶段 | 依赖 |
|---|---|
| P2 Agent 自主改进 | P1 |
| 脚本调用 | P2 |
| Session 监督树 | P1 |
| P3 渠道 | P1 |
| P4 Space v1 | P1 |
| P5 手机节点 | P4；跨节点委派还需要 Session 监督树 |
| P6 CP 加固 | P4 |
| 插件生态 | P4 |
| Windows 节点 | P0；参与 Space 还需要 P4 |

P2、Session 监督树、P3、P4 四个方向互不依赖，先做哪个取决于当时更需要什么。

**P2 Agent 自主改进**：Agent 能自己构建、部署和修复插件，并以评测衡量改进。每个机制都要有真实的使用者，P2 中没有使用者的推迟到它出现时：跨插件导入（插件生态）、插件状态（P3）、fs/shell 与记忆策略改为插件（之后）。契约也是如此：不为将来预留，需要破坏就升主版本（插件专题）。分九个里程碑实施（M19–M25 已验收），其余每个里程碑的计划在 [plan/](plan/)：

| 里程碑 | 一句话 |
|---|---|
| [M26 手册](plan/M26.md) | Agent 只读手册就能工作 |
| [M27 composer 插件](plan/M27.md) | Agent 以评测为目标迭代上下文策略 |

评测只在会改变 Agent 行为的里程碑运行（M23、M26、M27），退化的判定规则写在 [evals/README.md](../evals/README.md)；基础设施由集成测试验收。

验收：
- Agent 独立修复一个真实缺陷，并且**全程只读手册和插件源码，不需要读宿主源码**（M26）。这同时检验手册是否够用，以及双向不泄露是否成立。**验证第一个原始动机。**
- 披露策略被改坏后，安全模式仍能调用文件、Shell、`self_status`、`self_rewind` 与 `self_apply`（M27）。
- `plugin_rename` 之后，插件的代际历史与设置不变；只移动目录时登记被拦下，并提示改名用 `plugin_rename`；删除插件就是删掉目录再登记；复制出的目录在第一次登记时得到新身份（M24）。
- 插件导入 `completion` 在准入时被拒绝（M23）。
- `evals/` 的六道题都能端到端运行，基线写入运行结果；`adapter-drift` 经正式路径通过，让第一条验收可以重复检验（M19、M23、M26）。M23 的 `live-lookup` 已加入：答案只在拦截读取的官网上，经 Exa 回退才读得到，只查回答；web 的插件设置是变体的属性。
- 各里程碑推迟到阶段结束时一起做的手动核对：在 Telegram 中经 `self_apply` 换一次压缩模型并对话，再经 `self_rewind` 倒带撤销（M21、M24、M25）。

**脚本调用（工具多到逐个调用的代价明显时实施）**：宿主的脚本沙箱（QuickJS 编译为 Wasm）、嵌套调用的分派与记录、脚本内的 `capability_search` 与 `manual_read`，以及 composer 的披露形态选择（上下文专题）。
验收：一段脚本并行调用多个工具，模型只看到脚本的输出；脚本内搜索返回的能力可以调用，既未披露也未被搜索返回的被拒绝；被 `tool.gate` 拦下的嵌套调用在脚本中表现为失败；脚本在一次副作用调用之后抛错或被 `kill -9`，结算内容列出该调用及其结局，脚本不重跑。

**Session 监督树（需要多模型协作时实施）**：`session_delegate` / `session_send` / `session_read`、profile、Brief 作为 Attempt 用途、`ChildReturned` 回报、取消传播与限额（Session 专题）。
验收：父 Session 被取消后，所有子 Session 静止，未确认的副作用记为 `unknown`；子 Session 崩溃时父 Session 收到 `ChildReturned`，父 Session 被取消后不会被子 Session 的回报重新唤醒；父 Session 在子 Session 回报后可以继续给它发消息；发往树外的 `session_send` 返回 `failed`；崩溃恢复后委派不会重复创建子 Session；超过深度限制的委派返回 `failed`。

**P3 渠道插件化**：渠道接口就绪，Telegram 适配器改为 Wasm 插件，原生适配器删除；接入 QQ OneBot（宿主持有 WebSocket）。插件状态在这里第一次有使用者：渠道事件的转移带状态写入（归属与转移），`state-get` 与状态的作用域、数据形态在此时设计；如果更早出现有状态的工具插件，就在那时实施。
验收：有状态的调用并发不丢失更新，写入后 trap 的调用不留下写入；同一连接上相邻的两个事件跨代际处理时，游标与协议状态不倒退；在"入站接纳"与"游标提交"之间注入故障，不会确认一条尚未持久化的消息；兼容的替换不断线，不兼容的替换按协议重连补收；同一份制品以两份配置部署为两个代际。承诺的范围：对可重放的来源做到至少一次交付 + 本地去重；出站结果要么已知，要么为 `unknown`。

**P4 Space v1**：VPS + 桌面 + 见证者；控制平面（openraft）、粘滞所有权、roam、invoke、带 epoch 栅栏的日志复制、制品与已登记的源码按哈希分发、期望状态的 CAS、各节点的工作区跟上别处登记的意图（落后的工作区不能被当作新的意图登记）、渠道与定时的租约（定时触发按 `(schedule, due_at)` 在 Inbox 去重）、记忆的归属与复制（记忆专题）、数据库迁移。从 P4 起升级不丢记录；旧版本的节点和回滚后的宿主怎样读取新数据，也在这时确定。
验收：任务中途漫游到另一个节点后继续；漫游过程中断开连接不出现双 Round；杀掉 VPS 后 Telegram 租约在 TTL + ε 内转移到桌面，且全程不存在两个轮询者；少数派一侧的行为符合多节点专题；在桌面写入的记忆，Session 漫游到 VPS 后可以召回，更正与遗忘在各节点都生效。**验证第二个原始动机。**

**P5 手机节点**：learner 节点、进入后台前自动漫游回常驻节点、设备能力导出、跨节点委派。
验收：iOS 应用在任务中被切到后台后，任务在 VPS 上继续；VPS 上的 Session 可以调用手机相机。

**P6 CP 加固**：Jepsen 式故障注入（分区、时钟漂移、休眠与唤醒、租约期间 leader 变更、旧节点复活），强制接管与 `divergent_branch`。

**插件生态**：跨插件接口导入与宿主转发（插件专题，P2 中没有使用者而推迟；更早出现真实的插件间导入时就在那时实施）、外来插件的 `plugin_install` / `plugin_update`、采纳时的主人确认（已批准的集合包括导入与凭证，插件专题）、宿主同时链接 `enco:plugin` 的历史版本、`enco:plugin` 1.0、`enco-sdk` 按 semver 发布（插件专题）；采纳外来修订时检查其依赖的许可证与安全公告（cargo-deny）。这项检查要联网获取公告数据库，所以放在采纳流程和 CI 中，本地的 `cargo xtask check` 保持不依赖网络。
验收：安装一个第三方插件，并由另一个插件导入它导出的接口；回退一个被导入的插件后，依赖它的插件退出快照，原因写入 Log，对模型可见；上游更新扩大导入时停在待确认状态，确认前 home 和运行中的代际都不变；宿主升级 `enco:plugin` 主版本后，未重建的第三方插件照常运行；Agent 修好一个外来插件的缺陷，经主人确认后向上游提交 PR。

**Windows 节点（需要时实施，Unix 环境优先）**：本地端点在 Windows 上改用命名管道（tokio 不在 Windows 上提供 Unix domain socket），访问限定为当前用户；Shell 工具使用 PowerShell 7，工具描述按平台写明所用的 shell，输出按 UTF-8 解码；守护进程响应控制台关闭与系统关机；Unix 专用的测试按平台编译；CI 增加 Windows runner。参与 Space 之前补上计入休眠时间的时钟（多节点专题）。这些都是宿主的平台适配，不改变设计。
验收：`cargo xtask check` 在 Windows 上通过；CLI 经命名管道与守护进程完成对话，其他用户无法连接；`shell_exec` 正确返回中文输出。

**之后**：blob 回收（测出需要时实施；规则由引用推出：计划沿 M27 的父链保留，最近一次登记的源码保留，否则看不了未登记的改动；其余内容缺失时，对比与倒带明确报告缺失的登记与路径）、并行修改意图（多个 Agent 同时修改插件时实施，例如 Agent 团队；各自在独立的工作副本中修改（例如 git worktree），合并回 home 之后仍由 `self_apply` 一次登记整份意图，M24）、评测作为健康信号（Skills 与 AGENTS.md 成为指令代际，像插件源码一样按内容寻址登记，评测成功率下降即为失败信号；也用于只会语义退化的代际，例如 composer；难点在评测的噪声、成本与防止背答案，评测运行器可用且 Agent 开始频繁修改指令时实施）、fs/shell 工具改为 Wasm 插件与记忆策略改为插件（按需；原生版本保留为救生集）、定时工具改为插件（工具接口能调用内核命令时；Scheduler 与定时的持久化留在内核）、修改已有的定时（目前取消后重建）、`at` 接受不带偏移的当地时间、流式补全（有消费者时加入 `completion`，按插件专题的契约规则升主版本）、健康代际的降级、决策接口的更多用途（`tool.gate`、OpenAI 的 `/v1/decisions`）、Android 本机构建（Root/Shizuku + Ubuntu 中本机编译插件）、宿主自更新（主人确认；自主权限以后显式开通）、覆盖网络路由、Edge 节点（ESP32）、系统代际的整体回滚；MCP 接入（某个需要的服务只提供 MCP 时实施，需要先回答：外部进程提供的工具定义怎样钉进代际，stdio 服务作为宿主持有的资源，工具标注怎样映射到 effect 与 `outcome`；采纳 MCP 服务等于完全信任，插件专题）。
