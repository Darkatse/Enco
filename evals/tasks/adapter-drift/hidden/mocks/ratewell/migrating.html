Migrating from v1 to v2

v2 has been available since {{date:-120d|en}}. v1 was deprecated on {{date:-92d|en}} and retired on {{date:-1d|en}}; its endpoints now return 410 Gone.

Why v2

v1 let you pick any base currency and computed cross rates on our servers, rounded to six decimal places and returned as JSON numbers. That looked convenient, but it meant v1 quietly published numbers the ECB never did, and some clients lost precision parsing them as floats. v2 returns exactly what the ECB publishes and leaves the arithmetic to you.

What changed

v1v2
EndpointGET /v1/latest?base=USD&symbols=CNY,JPYGET /v2/latest
Base currencyAny, chosen with base (default EUR)Always the euro. The base parameter is gone.
Choosing currenciessymbolsGone. Every currency comes back in one response; pick what you need.
ratesAn object from currency code to numberAn array of { "currency", "rate" } objects
Rate valuesJSON numbers, rounded to six decimal placesDecimal strings with the ECB's own precision
Date fielddatepublished
Historical ratesGET /v1/{date}Not yet available

Side by side

v1:

GET /v1/latest?base=USD&symbols=CNY

{ "base": "USD", "date": "{{date:-75b}}", "rates": { "CNY": 7.218459 } }

v2:

GET /v2/latest

{
  "base": "EUR",
  "published": "{{date:-75b}}",
  "source": "European Central Bank, euro foreign exchange reference rates",
  "rates": [
    { "currency": "USD", "rate": "1.0835" },
    …
    { "currency": "CNY", "rate": "7.8212" },
    …
  ]
}

Cross rates

If your code asked v1 for a base other than the euro, compute the cross rate from the two euro rates. To convert an amount from currency A to currency B:

amount × rate(B) ÷ rate(A)

The euro is not in the rates array; treat its rate as 1. With the rates in the example above, 100 USD is 100 × 7.8212 ÷ 1.0835 = 721.85 CNY, the same answer v1 gave up to rounding.

The most common migration bug we have seen is reading the v2 rates as if they were quoted against your old base. A client that used base=USD and only renamed the fields will treat 7.8212, the yuan per euro, as yuan per dollar, and be off by the EUR/USD rate.

Checklist

  1. Point requests at /v2/latest and drop base and symbols.
  2. Read rates as an array and parse each rate from its string.
  3. Compute cross rates as above whenever neither side is the euro.
  4. Rename date to published wherever you show it.
  5. Cache the response until the next working day; one call covers every currency.

Stuck? Write to hello@ratewell.io with the request you send and the response you get.
